# Blazorly 0.17.0

A team chat stays readable when teammates report often. Teammate reports used to arrive as one steering message each, so a few teammates narrating their work could bury the conversation. Reports now fold: each teammate holds one pending row, and the newest note replaces the older one.

- **One pending row per teammate.** A teammate's report lands in your inbox as `[teammate <label>] report <id>`. If that teammate already has a report waiting, the new one replaces it and the header says how many earlier reports it supersedes. Three teammates sending six progress notes between them now add three rows, not six, and the row you read is always the newest state.
- **Reports carry who and what.** The header names the teammate, the report's message id, and the team task when the teammate tags one with the new optional `task_id`, so a report can be matched to the work it answers instead of read out of context.
- **Identical repeats stay out of the conversation.** A repeat of the last waiting report from the same teammate is recorded in the team mailbox and not delivered again. The check lapses with the pending row, so the same wording after new work still reaches you.
- **Automated notices are capped, your own steering is not.** At most eight folded notices stay pending; beyond that the oldest is dropped. Steering you type is never evicted, and if nothing foldable is pending the queue is allowed to run past the cap rather than lose input.
- **Long reports are bounded.** A report body is truncated at 4000 characters, so one teammate's full write-up cannot crowd out the rest of the queue.

## Upgrade notes

- Restart the app to pick up the new inbox behavior.
- No settings migration is required. `report` takes an optional `task_id`; teammates that call it with `summary` alone keep working unchanged.
- Reports already waiting in a queue are unaffected. Folding applies to reports that arrive after the upgrade.
- The team mailbox in the session log still records every report delivery, including the ones deduplicated out of the conversation. Roster, task board, and `send_message` behave as before.
- `send_message` still waits for the teammate's reply. Folding keeps the queue proportional to the team while the lead waits, but it does not shorten that wait; batch several `send_message` calls when several teammates have work to do.
