# Blazorly 0.14.0

The harness gets a desktop app. Same engine, same sessions, same workspaces — now in a native window with a tray, menu bar, and `blazorly://` links, released alongside the CLI for the first time.

- **Blazorly Harness for macOS.** An Electron shell that finds your engine or starts one for you. If you already run the browser UI on port 5080, the app attaches to the same engine — chats, workspaces and settings are literally the same. Otherwise it starts its own engine, on a fallback port it remembers, and stops it again when you quit. The app bundles the exact engine archive this release ships, so the desktop and `blazorly` never drift apart.
- **Install it** with `installer/install-desktop.sh` (downloads, verifies the checksum, installs to `/Applications`), or grab `Blazorly Harness-0.14.0-arm64.dmg` from the release assets. Apple Silicon only for now.
- **Native habits.** Inset title strip with proper traffic lights, a tray that shows engine status and offers New Chat / Restart Engine, `⌘N` / `⌘,`, a branded startup screen while the engine warms up, and honest failure screens — if the engine can't start, you get the stage, the message, and the log, never a blank window.
- **Remote engines work too.** `--attach "http://host:5080/?token=…"` connects to a token-gated engine anywhere (the shell does a Bearer check and installs the session cookie itself — the token never lands in the URL bar). For anything beyond localhost, the engine's SSH-tunnel advice still applies and is the recommended path.
- **Releases now build both.** Tagging `v*` publishes the six CLI archives and the macOS desktop app, with desktop checksums (`SHA256SUMS-desktop`) alongside them.

## Upgrade notes

- Existing installs are unchanged: `blazorly update` and the install scripts keep doing exactly what they did. The desktop app is additive.
- The desktop app is ad-hoc signed for this first release, so macOS asks once — right-click → Open. Signed and notarized builds switch on automatically once the Developer ID secrets are added to the release workflow (documented in `desktop/README.md`).
- The app keeps its own preferences in `~/Library/Application Support/Blazorly Harness` (logs included); engine data stays in `~/.blazorly` and is shared with the CLI.
