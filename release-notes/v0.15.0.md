# Blazorly 0.15.0

Answers get easier to read, and spending tokens becomes a choice you control. Final answers now lead with a short, plain-language result that anyone can stop at, diagrams draw as pictures in the chat, and a new Token saver page collects four opt-in ways to cut token use — tool-output compression, terse output, minimal-code bias, and Headroom context compression.

- **Plain-language answers.** Every answer now starts with **What happened** — the result in one to three short, plain sentences (short sentences, active voice, common words, technical terms explained once). **What you need to do** follows when you have a step to take, and exact files, tests, and errors sit in a **Technical details** part below for anyone who wants them. Progress updates while the agent works follow the same plain style.
- **Choose your answer style.** **Settings → Answers** offers *Plain first, details below* (the new default), *Plain only*, and *Technical* — the previous engineer report. Each card carries a "See an example" preview. The choice (`answerStyle` in `settings.json`) applies to every workspace and reaches open chats on their next message, no restart.
- **Diagrams in chat.** When an answer explains a process of three or more steps, the agent can include a Mermaid diagram. The chat now draws it as a picture, themed to your appearance, with the diagram text kept under a small toggle. Mermaid is vendored and loads only when a diagram appears, so it works offline. A diagram that cannot be drawn stays visible as text with a plain note saying so.
- **Token saver: compress tool output.** Built-in RTK-style filtering reshapes the noisiest tool output before the model reads it — `git status` grouped by section, `git log` down to hash and subject, `git diff` with context cut around changes, search results grouped by file, file listings grouped by folder, repetitive log lines collapsed. File contents are never filtered, unknown shapes pass through untouched, failed commands keep their full error text, and a `[compressed by token saver: …]` line marks what was shrunk. The settings page counts the savings since the app started. Following [RTK](https://github.com/rtk-ai/rtk), which measures 60–90% fewer tokens on this kind of output.
- **Token saver: terse output and minimal code.** *Terse output* ([Caveman](https://github.com/JuliusBrussee/caveman) style) answers in short fragments — code, commands, and errors stay exact, safety warnings stay in full sentences. *Minimal code* ([Ponytail](https://github.com/DietrichGebert/ponytail) style) biases the agent to skip what is not needed, reuse what exists, prefer the standard library, and delete over add — without ever cutting validation, security, or tests for risky logic.
- **Token saver: Headroom context compression.** Route model requests through a [Headroom](https://github.com/chopratejas/headroom) proxy you install and run (`uv tool install "headroom-ai[proxy]"`, then `headroom proxy --port 8787`). The whole prompt is compressed before it reaches the model; each route's real provider address travels in the `x-headroom-base-url` header, so every provider keeps working. A **Check proxy** button on the settings page confirms the proxy answers before you rely on it.
- **Cleaner settings pages.** Answers and Token saver are rebuilt as cards with proper on/off switches, one-line summaries, and "How it works" accordions holding the long explanations — the walls of text and small checkboxes are gone.

## Upgrade notes

- **Answer format changes by default.** The layered plain-first style applies to every workspace, including ones with custom Agent setup instructions (it ships as its own prompt section). To restore the previous engineer report exactly, pick **Technical** in Settings → Answers. Structured sub-agent results (swarm/review JSON) are exempt in every style, so delegation formats never change.
- **Token saver changes nothing until you turn it on.** All four switches default off. Terse output pauses your Answers style while it is on; the other three compose with it.
- **Headroom is external and optional.** The harness never installs or starts it. Two Headroom safety rules to know: it refuses private or local provider addresses unless you start the proxy with `HEADROOM_ALLOWED_BASE_URLS` naming them, and gateways with deeper address paths (like `…/api/paas/v4`) may not route through it. Public providers ending at the host or `/v1` work as-is. If the proxy is not running while enabled, model requests fail with a connection error rather than silently bypassing it.
- **New settings keys** (`answerStyle`, `tokenSaver*`) appear in `settings.json` on first save; older files load with the defaults above. The vendored diagram library adds about 2.6 MB, loaded only when a diagram renders. No CSS token names changed; custom CSS keeps working.
- Dependencies were refreshed across projects. Restart the app to pick up the release.
