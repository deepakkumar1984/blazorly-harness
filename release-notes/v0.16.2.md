# Blazorly 0.16.2

This patch makes OpenAI-compatible gateway routing and retry diagnostics follow what the provider actually supports.

- **Gateway prefixes select routes, not protocols.** GPT-5 and GPT-6 ids remain on Responses only when unprefixed or under the `openai/` namespace. Ids such as `az/`, `azure/`, and `openrouter/` start on Chat Completions, avoiding gateways rewriting Responses-only fields into parameters Azure rejects.
- **Token field negotiation preserves the requested budget.** If a route rejects `max_tokens` in favor of `max_completion_tokens` (or vice versa), the harness retries with the accepted field and keeps the configured output limit.
- **Rejected reasoning effort gets one clean retry.** When a provider explicitly names effort as unsupported, the harness retries once without it and records the downgrade in the trajectory instead of failing silently or changing the token cap.
- **Upstream dependency failures are reported honestly.** Gateway errors such as `BadRequestForDependentService` no longer trigger five token-cap reductions or blame reasoning effort and max output. The turn fails once with the provider's error and advises retrying later or selecting another model.

## Upgrade notes

- Restart the app to use the new routing and retry behavior.
- No settings migration is required. Existing providers, models, effort levels, and output limits are unchanged.
- A provider route that is failing upstream still needs to recover. When another model on the same gateway works, select that model instead of changing the failing route's parameters.
