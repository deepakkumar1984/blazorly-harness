# Blazorly 0.11.1

Long chats stay responsive. A session with thousands of messages no longer gets heavier as it grows — the transcript refresh that runs several times a second was re-reading the whole session log on every tick.

- **Fixed the drag in long sessions.** Each tick copied the entire event log twice and rescanned it for the title, the permission preset, the plan-mode chip and the newest failed turn. That state is now folded once as events arrive, so a tick costs the same at 20,000 events as at 200 — measured on a 16,000-event session, ~1.5ms per tick down to ~0.001ms.
- **Tool cards settle faster.** Matching a tool result to its card walked the whole transcript; it is now a direct lookup.
- **Bounded transcript memory.** The page holds the newest 2,000 transcript nodes instead of every node for the life of the tab, and releases a step's streaming buffer once it settles. Nothing is lost — **Show earlier messages** re-folds on demand and still reaches the first message.
- An event that cannot be rendered now reports its error chip where it happened, instead of at the bottom of the transcript.

## Upgrade notes

- Restart the app to pick up the release. No settings or workspace changes needed.
